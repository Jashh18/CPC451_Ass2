Java source code
@Override
protected void map(LongWritable key, Text value, Context context) {

    // Normalise: remove punctuation, lowercase
    String line = value.toString()
        .replaceAll("[^a-zA-Z0-9\\s]", "").toLowerCase();

    StringTokenizer tokenizer = new StringTokenizer(line);

    while (tokenizer.hasMoreTokens()) {
        word.set(tokenizer.nextToken());
        // Emit (word, 1) for every token
        context.write(word, ONE);  // ONE = new IntWritable(1)
    }
}

// Optimisation: reuse objects instead of creating millions of
// short-lived instances → reduces Garbage Collection pressure
private final static IntWritable ONE  = new IntWritable(1);
private final Text               word = new Text();
    
@Override
protected void reduce(Text key, Iterable<IntWritable> values, Context context) {

    int sum = 0;

    // Hadoop guarantees: ALL (word, 1) pairs for the same word
    // land on the same Reducer call — just sum them up.
    for (IntWritable val : values) {
        sum += val.get();
    }

    result.set(sum);
    context.write(key, result);  // emit (word, totalCount)
}

private final IntWritable result = new IntWritable();
    
Job job = Job.getInstance(conf, "Word Count");
job.setJarByClass(WordCountDriver.class);

// Wire up Mapper and Reducer
job.setMapperClass(WordCountMapper.class);
job.setReducerClass(WordCountReducer.class);

// KEY OPTIMISATION: Combiner = mini-reducer on each Map node.
// Aggregates locally BEFORE the shuffle → far less network traffic.
job.setCombinerClass(WordCountReducer.class);

job.setOutputKeyClass(Text.class);
job.setOutputValueClass(IntWritable.class);

FileInputFormat.addInputPath(job, new Path(args[0]));
FileOutputFormat.setOutputPath(job, new Path(args[1]));

boolean success = job.waitForCompletion(true);

java -version && mvn -version

wget https://downloads.apache.org/hadoop/common/hadoop-3.3.6/hadoop-3.3.6.tar.gz
tar -xzf hadoop-3.3.6.tar.gz && sudo mv hadoop-3.3.6 /opt/hadoop
echo 'export HADOOP_HOME=/opt/hadoop' >> ~/.bashrc && source ~/.bashrc
Add HADOOP_HOME/bin to PATH as well: export PATH=$PATH:$HADOOP_HOME/bin:$HADOOP_HOME/sbin

Build the JAR with Maven
cd hadoop-wordcount && mvn clean package -DskipTests
Output: target/wordcount-1.0.jar
4
Start HDFS & YARN (pseudo-distributed mode)
$HADOOP_HOME/bin/hdfs namenode -format
$HADOOP_HOME/sbin/start-dfs.sh && $HADOOP_HOME/sbin/start-yarn.sh
jps

Upload input & run the job
hdfs dfs -mkdir -p /user/$USER/input

hadoop jar target/wordcount-1.0.jar com.wordcount.WordCountDriver /user/$USER/input/sample.txt /user/$USER/output

View the results

MapReduce optimisations
◈ Combiner (Local Pre-Reduction)
Runs the Reducer logic on each Mapper node before the shuffle phase. Dramatically reduces network I/O — instead of shipping thousands of (hadoop, 1) pairs, it ships one (hadoop, 45).
◈ Object Reuse
Reusing IntWritable and Text objects instead of creating new ones per token cuts millions of small object allocations — reducing Garbage Collection pauses on the JVM.
◈ Input Splitting
HDFS splits large files into 128 MB blocks automatically. Each block is processed by a separate Mapper in parallel — linear scalability with file size.
◈ Text Normalisation
Converting to lowercase and removing punctuation ensures "Hadoop", "hadoop," and "HADOOP" are counted as one word — critical for accurate results on real-world text.
◈ Data Locality
Hadoop schedules each Mapper on (or near) the node storing its input block. This "move computation to data" principle avoids expensive network transfers of raw data.
◈ Speculative Execution
Hadoop can run duplicate copies of slow (straggler) tasks on other nodes and use whichever finishes first — improving overall job completion time on large clusters.
